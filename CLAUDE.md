# CragMatch

Climbing trip finder for groups of friends leaving from Barcelona: find
sectors that fit everyone's grades, distance and styles, then a place to stay.
Full file tree and run instructions: `README.md`.

## Stack
- Backend: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0, Alembic, uv.
- Database: Postgres 17 + PostGIS + pgvector in Docker on host port 5433
  (5432 is taken by a native Postgres on this machine).
- AI: Claude via the Anthropic SDK (`app/services/llm.py`), Voyage
  `voyage-3.5` embeddings, 1024 dims (`app/services/embedding.py`).
  Stage 6 LangChain/LangGraph code lives in `app/rag/`.
- Frontend: React 19 + TypeScript + Vite.

## Commands
Backend commands run from `backend/`, frontend commands from `frontend/`.
- `docker compose up -d` (repo root): start the database
- `uv run fastapi dev app/main.py`: API on :8000, docs at /docs
- `uv run pytest`: all tests; must stay green before any commit
- `uv run pytest tests/test_groups_api.py::test_name -x`: one test, stop on first failure
- `uv run alembic revision --autogenerate -m "..."` then `uv run alembic upgrade head`
- Fresh DB: seed scripts in README "Running locally" (order matters;
  `embed_sectors` hits Voyage's 3 req/min limit)
- `npm run dev`: frontend on :5173
- `npm run lint`: ESLint, must pass for frontend changes

## Architecture rules
- Routers are HTTP only: validate input, call a service, turn errors into
  HTTPException. Logic lives in `app/services/`.
- `services/group_matching.py` is pure (no DB, no HTTP). It only reads
  attributes, so tests pass plain stand-in objects. Keep it that way.
- Schemas (`app/schemas/`) are separate from models (`app/models/`).
  Endpoints declare `response_model`; read schemas use `from_attributes`.
- A new model must be imported in `app/models/__init__.py`, then get an
  Alembic migration. Review autogenerated migrations: `alembic/env.py`
  only compares our own tables (PostGIS adds many it must ignore).
- Settings come from `app/core/config.py` (pydantic-settings, env prefix
  `CRAGMATCH_`, file `backend/.env`). Never hardcode keys or passwords.

## Reuse before writing
- Distance: `haversine_km()` and `BARCELONA` in `services/geo.py`.
- Sector filtering: `find_matching_sectors()` in `services/search.py`
  (raises ValueError on bad input; the router maps it to 400).
- Group logic: `merge_preferences()` (strict) and `score_sectors()` /
  `why_not()` (scored) in `services/group_matching.py`.
- Stays: `find_stays_near()`, `airbnb_url()`, `booking_url()` in `services/stays.py`.
- Claude calls: the client, `LLM_MODEL` and `log_usage()` in `services/llm.py`.
- Embeddings: `embed_query()` and `EMBED_MODEL` in `services/embedding.py`.
- FastAPI dependencies: `get_db` (`core/dependencies.py`), `get_group` /
  `get_member` (`routers/groups.py`), `load_sector` (`routers/sectors.py`).
- Frontend: `apiRequest()` and `errorMessage()` in `api.ts`; grades/styles in
  `constants.ts`; `types.ts` mirrors the backend schemas (update both together).
- Grades: `GRADE_ORDER`, `grade_rank()` (raises ValueError for an unknown
  grade), `ranges_overlap()` in `services/grades.py`. Never compare grade
  strings directly ("6a" < "6a+").


## Code standards
- Type hints everywhere; SQLAlchemy 2.0 style (`Mapped[...]`, `mapped_column`).
- Comments explain *why*, not what. Match the density of the surrounding file.
- Small functions, readable names, no clever one-liners.
- "No result" is a normal answer, not an exception (e.g. a group with no
  common ground gets `conflicts`, not an error).
- Frontend: function components and hooks; derive values instead of storing
  them in state; follow the `react-hooks` lint rules.

## Tests
- pytest with an isolated `cragmatch_test` database (`conftest.py`); the rate
  limiter is disabled in tests.
- Tests never touch the network: Claude, Voyage and Overpass are always mocked
  (monkeypatch where the router/service *uses* the function).
- New logic needs tests: pure functions get unit tests, endpoints get
  TestClient tests (happy path + main error cases).

## Traps
- Tests build their schema with `create_all()`, not migrations, so green tests
  don't mean the dev DB is current. After pulling or delivering a migration, run
  `uv run alembic upgrade head`. "UndefinedColumn" on the dev server means you skipped it.
- Rate-limited endpoints (slowapi) must take a parameter named `request: Request`;
  the JSON body is therefore named `body`.
- Voyage free tier: 3 requests per minute. Scripts that embed must batch or wait.
- Windows + OneDrive: stop the dev server before `uv add` / `uv sync`
  (locked files cause "Access is denied").
- Stop a process only by its exact, verified PID, never by matching
  command-line text (that has killed the Vite server before).
- `pgvector` is pinned `<0.4` because `langchain-postgres` requires it.
- LangChain's PGVector uses its own tables (`langchain_pg_*`), separate from
  `sectors.embedding`.

## Security
- Never read, print or commit `backend/.env`. Only `.env.example` (blank values)
  is committed.
- No real API keys, passwords or personal data in code, tests or commits.

## Workflow
Idea → `/qualify-ticket` (product-owner) → `tickets/NNN-*.md` → `/write-resolution-plan`
(tech-lead) → `NNN-*.plan.md` → `/deliver-increment` (developer builds one increment,
tech-lead reviews). Hooks in `.claude/hooks/`: block `.env` access, lint each edited
file, run backend tests when the developer agent finishes (and before Claude
stops if it edited backend Python), and keep
the product-owner and tech-lead writing only in `tickets/`.

## Definition of done
1. Tests pass (`uv run pytest`) and lint passes for frontend changes.
2. Model changes come with a reviewed migration.
3. New files or folders are added to the structure in `README.md`.
4. Commit messages say what changed and why, one step per commit.
