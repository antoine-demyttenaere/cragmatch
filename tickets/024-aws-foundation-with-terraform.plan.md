# Plan for 024: Deploy on AWS, part 1: the foundation as Terraform

**Ticket:** `tickets/024-aws-foundation-with-terraform.md`
**Approach:** One small Graviton EC2 host (`t4g.small`) in one public subnet with **no inbound rules**
runs Postgres 17 with PostGIS and pgvector in a container built from a new multi-arch recipe. The data
lives on its own encrypted EBS volume with daily snapshots, and the password is generated by Terraform
and stored only as a write-only SSM SecureString. Ticket 025 adds the backend container to the same host
behind CloudFront. Around it: Terraform >= 1.11 with an S3 state bucket (versioned, S3 lockfile), created
by a bootstrap stack whose own state is then migrated into the bucket; a monthly budget that emails the
owner; default `Project` tags; a GitHub OIDC deploy role trusted only for `main`; offline `terraform test`
with mocked providers; and a separate `Terraform` workflow, so ticket 018's `CI` workflow is not touched.

Assumed delivered first, as their plans describe: 017 to 023 (021's image and settings, 022's cap,
023's `load_data`). Nothing in `backend/` or `web/` changes here.

**Network traps:** a NAT gateway costs 35.04 a month and an ALB 18.40 a month, before any traffic.
Either one alone breaks the budget, so the design has neither. Every public IPv4 costs 3.65 a month,
whether attached or idle, so there is exactly one (an Elastic IP).
**Secrets:** SSM Parameter Store standard parameters are free, with the AWS-managed `aws/ssm` KMS key.
Secrets Manager costs 0.40 per secret a month (1.20 for the three secrets). Chosen: Parameter Store.
**Frontend hosting (026):** a private S3 bucket behind CloudFront with the default `*.cloudfront.net`
certificate. CloudFront pay-as-you-go includes 1 TB and 10 million requests free each month (price list).
The flat-rate Free plan is also 0 USD (1M requests, 100 GB), but it lacks VPC origins (not used). S3
storage for `dist/` costs well under 0.01 a month. 025 adds about 0.10 to 0.20 (ECR storage at
0.10/GB-mo, log volume within the free allowance). 026 adds about 0.01.

**Credits and free tier (account status unknown, both planned):** new accounts get USD 100 at sign-up and
can earn up to USD 100 more. The **Free plan** lasts at most 6 months; after that the account closes and
the data is deleted after 90 days unless it is upgraded. The **Paid plan** applies the credits and then
bills. The FAQ gives two expiry dates: 6 months (sign-up credits under the new sign-up experience of
October 2026) and 12 months (when upgrading to the Paid plan). The runbook tells the user to read the
date on their own Credits page. At 18.8 USD a month, USD 100 lasts about 5 months. During the T4g trial
(about 5.4 a month) the credits outlast their expiry. The T4g trial (750 hours of `t4g.small` a month
until 2026-12-31) applies to **all** customers on both plans. Surplus CPU credits are billed, so the plan
sets `cpu_credits = "standard"`.

**Region: `eu-west-1` (Ireland), a variable.** It has the same price as Spain (`eu-south-2`) for
`t4g` (0.0184/h) and is cheaper for RDS (0.017 against 0.018). Every service is on by default there.
`eu-south-2` is an opt-in region, which means an extra enable step and regional STS details, and App

latency does not matter for static files behind CloudFront. The extra 30 to 40 ms to Ireland is nothing
next to a Claude call. The code works in `eu-south-2` once the region is enabled.

## Platform decision (this shapes 025 and 026)
- **Compute and database:** one EC2 `t4g.small` (arm64, Amazon Linux 2023) runs Docker. Postgres runs
  there now (024); the backend container joins it in 025. Each is a systemd unit, so there is no compose
  plugin to download. One host means **exactly one backend instance** by construction, which is what
  slowapi's in-memory limits need. The host never sleeps, so 025 AC 14 and 026 AC 12 are dropped ("the
  backend never sleeps").
- **Network:** one VPC, one public subnet in one AZ, an internet gateway, no NAT, no load balancer, and
  one Elastic IP on a pre-created network interface. The host security group has **no inbound rule**.
  It only allows outbound TCP 443 (Anthropic, Voyage, huggingface.co, Docker Hub, PGDG, AL2023 repos,
  SSM). Admin access goes through SSM Session Manager (no SSH, no key pair). Postgres is published only
  on the host's `127.0.0.1:5432` and on the Docker network `cragmatch` as `db:5432`, and it accepts TCP
  only over TLS. A private subnet is not used, because it would need the NAT gateway to reach the APIs.
  The protection is the empty inbound rule set plus loopback binding plus TLS with a password.
- **Database:** Postgres 17 from `infra/main/host/db/Dockerfile` (`postgres:17-trixie`, PGDG
  `postgresql-17-postgis-3` and `postgresql-17-pgvector`). It is built on the host at boot. Its data sits
  on its own encrypted gp3 volume, which survives instance replacement, with DLM snapshots daily, kept
  7 days.
- **Secrets:** SSM Parameter Store SecureString under `/cragmatch/...`. The database password is created
  by Terraform as an ephemeral random value written with `value_wo`, so it is never in the plan or the
  state. The Anthropic and Voyage keys go to `/cragmatch/api/anthropic_api_key` and
  `/cragmatch/api/voyage_api_key`. Ticket 025 creates those slots, and the user enters the keys by hand.
- **Deploy identity:** the GitHub OIDC provider and the role `cragmatch-github-deploy`, trusted only for
  `repo:<owner/name>:ref:refs/heads/main`. The role has **no permissions yet**: 025 attaches ECR push and
  SSM Run Command on the host, 026 attaches S3 sync and a CloudFront invalidation.
- **Toolchain:**
  - Terraform `>= 1.11.0` (write-only arguments). CI pins 1.16.6, the latest; locally 1.15.8 is
    installed and works.
  - Providers `hashicorp/aws ~> 6.68` (6.68.0 released 2026-10-07) and `hashicorp/random ~> 3.9`
    (ephemeral `random_password`).
  - S3 backend with `use_lockfile = true`. DynamoDB locking is deprecated, so there is no table.
  - Checks: `terraform fmt`, `validate`, offline `terraform test` with `mock_provider "aws"`, tflint
    v0.64.0 with the AWS ruleset v0.49.0 (its `aws_resource_missing_tags` rule enforces AC 10), and
    shellcheck on the host scripts.
  - All of these run in a new workflow `.github/workflows/terraform.yml`. `ci.yml` keeps its name `CI`,
    its jobs `tests`, `ruff`, `eslint` and their names unchanged.

**Alternatives considered (beyond the table):**
- *Change the repo's `postgres.Dockerfile` to the multi-arch recipe instead of adding a cloud one:* one
  recipe everywhere would be cleaner. But the local data volume was created by a bullseye-based image.
  Moving to trixie changes glibc collations (REINDEX needed), and the local PostGIS objects would be 3.5
  under a 3.6 library. 018's CI and the dev database would change in a ticket that promises no app
  change. So the cloud recipe is separate. It builds on amd64 too (the CI job tests it there), and moving
  local to it can be a later ticket with a fresh local volume.
- *x86 `t3a.small` with the repo's own image:* 14.89 a month and no free trial. That is about 15 USD more
  over the next 2.5 months, and 1.46 more a month after. Out.
- *Pull `postgis` from a community multi-arch image:* a third-party image for the most important data.
  Out.
- *DynamoDB lock table:* deprecated by Terraform. Out.
- *RDS-managed master secret in Secrets Manager:* 0.40 a month, and it rotates every 7 days by default,
  which a long-running app must handle. Not needed, because we do not use RDS.
- *`random_password` resource:* it puts the password in the state. The ephemeral variant with `value_wo`
  does not.
- *Bootstrap state kept local forever:* it breaks AC 12 for the bootstrap. Instead, a local-backend
  override file is used for the first run, and then `init -migrate-state` moves the state into the
  bucket. I checked locally that the override works.
- *Terraform job inside `ci.yml`:* possible (018 allows added jobs), but every push would download the
  AWS provider. A separate workflow with a `paths:` filter leaves 018's three checks exactly as they are.

## Ticket check
Checked against the code on 2026-10-14. `uv run pytest --collect-only -q` collected **199 tests**.
No other test ran, because the test DB is shared. No `terraform` command touched AWS.
- **Correct:**
  - There is no Terraform and no `.github/` today.
  - `postgres.Dockerfile` is `postgis/postgis:17-3.5` plus apt `postgresql-17-pgvector`.
  - `vector` is created by `178caab75ad8`, whose downgrade does not drop it, and by `conftest.py`.
  - No code, model or migration creates or uses `postgis`. The only mention is a comment in
    `alembic/env.py:77`.
  - `alembic/env.py` compares only our own tables.
  - Connections are 15 for the app engine (SQLAlchemy defaults 5 + 10, `core/database.py`), 15 for
    PGVector's own engine (`rag/vectorstore.py`) and 5 for the planner pool (`POOL_MAX_SIZE`,
    `agent/checkpointer.py`). That makes **35 per process**, about 38 with Alembic and a load running.
    Our Postgres keeps the default `max_connections = 100`, and the CI check asserts at least 50.
  - `setup()` builds indexes CONCURRENTLY. The database user is the image's `POSTGRES_USER`, a
    superuser, so it has every right it needs (the same as local).
- **Wrong or missing in the ticket, and what is true:**
  - **"Postgres in a container or VM with the repo's own image":** that image cannot run on Graviton.
    `postgis/postgis:17-3.5` has only an amd64 image (Docker Hub, 2026-10-14). The cloud database needs
    its own multi-arch recipe (see Alternatives). PostGIS in the cloud is 3.6.x (local is 3.5); pgvector
    is 0.8.x in both.
  - **AC 4 "laid out so the database is not reachable":** a private subnet would need a NAT gateway
    (35.04 a month, more than the budget) for the outbound API calls, because Voyage and the HF CDN have
    no IPv6. The layout is one public subnet with no inbound rules, and the database bound to loopback
    and the Docker network. The plan says so in the runbook.
  - **AC 5 "reachable from the network and from the later backend service":** "the network" is the
    host's Docker network `cragmatch` (the backend, 025) and SSM port forwarding from the laptop (the data
    load, 025). Nothing else in the VPC exists to reach it.
  - **AC 6:** `postgis` and `vector` are created by an **infrastructure step**, the image's init script on
    the first start of an empty data directory. This mirrors local, where the `postgis/postgis` image
    creates `postgis` and the migration creates `vector`. The migration's `CREATE EXTENSION IF NOT EXISTS
    vector` then does nothing. The local image also adds `postgis_topology`, `fuzzystrmatch` and
    `postgis_tiger_geocoder`. The cloud recipe adds only the two, and no other extension is created,
    changed or dropped.
  - **AC 12 "a second apply changes nothing":** this only holds because the plan pins the AMI
    (`ignore_changes = [ami]`) and keeps the password's `value_wo_version` fixed. Otherwise every new
    AL2023 image or every run would show a change. OS updates are a deliberate `-replace` (runbook).
  - **App Runner** (implied in 025's notes) no longer accepts new customers.
  - **Free tier:** the 12-month free tier is gone for new accounts (credits replace it). Separately,
    "Always Free" Lambda (1M requests, 400,000 GB-s) and CloudFront pay-as-you-go (1 TB, 10M requests)
    allowances exist, and the T4g trial runs until 2026-12-31.
  - **Budget currency:** AWS bills in USD by default, so the thresholds are set in USD at the ECB rate:
    limit 11.20 USD (about 10 EUR), with alerts at 50% and 100% of it.
  - **"Depends on: nothing in the app":** true for building it. But cut 1 (`t4g.micro`) depends on the
    memory ticket 021's hand-off measures. Without that number the default stays `t4g.small`.
- **On this machine** (not read, only seen by listing the folder): `~/.aws/credentials` already exists.
  So the provider gets `allowed_account_ids = [var.aws_account_id]`, and a plan against the wrong
  account fails at once. The runbook starts with `aws sts get-caller-identity`.

## Risks
- **Data loss on the host:** the two guards are format-only-if-empty and `RequiresMountsFor`. The
  reviewer reads both lines, and manual check B6 (replacement drill) proves them before 025 puts friends'
  data there. One AZ and one volume: an AZ outage means downtime, and losing the volume means restoring
  the last snapshot (at most 24 hours old). High availability is out of scope.
- **The trial ends on 2026-12-31:** the bill goes from about 5 to about 19 USD a month. The budget's
  50% and forecast alerts fire in early January; the runbook's dated section gives the cuts. Cut 1
  needs the memory measured (021's hand-off, then 025 on the host). About 400 to 600 MB for the app plus
  about 200 MB for Postgres, on 1 GiB with swap, is a guess, not a number.
- **New-account rules (October 2026):** the Free plan closes the account after 6 months. "Advanced
  features" may be needed for IAM roles or other regions. The credit expiry is stated as 6 or 12 months
  in different FAQ answers. The runbook tells the user to check their own account; none of it changes
  the code.
- **Credentials already on this machine:** `allowed_account_ids` refuses any other account, and the
  runbook checks `get-caller-identity` first. Agents never run plan or apply against AWS.
- **Boot depends on outside services:** Docker Hub (anonymous pull limits), PGDG apt, the AL2023 repos
  and SSM. If one fails, the boot log shows it and re-running `host-setup.sh` through SSM finishes the
  job (it is idempotent).
- **Version drift:**
  - every rebuild takes the newest PostGIS 3.6.x and pgvector 0.8.x;
  - an existing database keeps its extension versions until `ALTER EXTENSION ... UPDATE`;
  - a Postgres major upgrade (17 to 18) is a manual dump and restore. That is the price of option A
    over RDS, and the runbook says so.
- **OS updates:** the AMI is pinned (`ignore_changes`), so the host does not update itself. The runbook
  says to replace it monthly, or to run `dnf upgrade` through SSM.
- **Security trade-offs, written in the runbook:**
  - the app user is the database superuser (the same as local, and it makes `setup()` and
    `CREATE EXTENSION` work);
  - the host is in a public subnet, with no inbound rule, no SSH and Postgres on loopback only;
  - the Postgres certificate is self-signed (025 can verify it against the cert on the data volume);
  - 025 must decide how CloudFront reaches the host (HTTP origin, inbound only from CloudFront's
    managed prefix list).
- **State contents:** no password, thanks to write-only arguments; the email, the account id inside ARNs
  and the public IP are in it. The bucket is private, encrypted, TLS-only and versioned.
- **Mocked tests prove configuration only:** a wrong ARN format or an IAM rule AWS rejects shows up only
  on the user's first `plan`/`apply`. tflint's AWS ruleset catches invalid instance types and similar.
- **The hook `protect_env.py`:** any shell command containing `.env` is blocked, hence
  `db-environment`. The developer must not name host files `*.env`.
- **Size:** about 30 files, almost all declarative, plus about 25 test runs and a runbook. One
  delivery, as the ticket's "L" expects. If the review finds it too big, split the **ticket**:
  - 024a: state, budget, tags, OIDC, Terraform CI;
  - 024b: network, host and database.
- **Behaviour that must stay unchanged:**
  - `backend/`, `web/`, `postgres.Dockerfile`, `docker-compose.yml` and `.github/workflows/ci.yml` are
    untouched;
  - local development and the 018 checks behave as before;
  - `backend/.env` is never read or used.
- **No migration:** nothing to downgrade. AC 6 relies on migration `178caab75ad8` staying as it is.

## Seams for 025 and 026 (what they build on)
- **Host:**
  - outputs `host_instance_id`, `host_public_dns` and `host_public_ip` (stable, Elastic IP);
  - `host_security_group_id`: 025 adds the only inbound rule, TCP 80 from the managed prefix list
    `com.amazonaws.global.cloudfront.origin-facing`. It weighs about 55 rules against the default quota
    of 60 per group, so keep it the only inbound rule;
  - `host_role_name`: 025 adds ECR pull and `/cragmatch/api/*` reads; the existing policy already covers
    `/cragmatch/*`;
  - arm64, 2 GiB plus 1 GiB swap;
  - IMDSv2 with hop limit 1, so containers get no AWS credentials; the host passes secrets in.
- **Database for the backend container:**
  - the Docker network `cragmatch`, host `db`, port 5432, user and database `cragmatch`, password at
    `/cragmatch/db/password`;
  - TLS required: `PGSSLMODE=require`, or `verify-full` with `/srv/cragmatch/pgtls/server.crt` mounted
    as `PGSSLROOTCERT` (the cert names `db`);
  - 021's five `CRAGMATCH_POSTGRES_*` parts fit directly.
- **Pattern for the backend:** a second systemd unit like `cragmatch-db.service`, written into the same
  `user_data` (the host is replaced, the data kept) or installed by the deploy through SSM Run Command.
  Before restarting it, run migrations as a one-off
  `docker run --rm --network cragmatch <image> alembic upgrade head`; the old container keeps serving
  until then. Mount a host folder for `HF_HOME` so the tokenizer survives restarts.
- **Data load (023):** SSM port forwarding (`AWS-StartPortForwardingSessionToRemoteHost` to
  `127.0.0.1:5432`) from the laptop, then `load_data` with
  `CRAGMATCH_POSTGRES_URL=postgresql://cragmatch:<password>@localhost:<port>/cragmatch?sslmode=require`.
  `import_stays` keeps running on the laptop.
- **Client address:** with no ALB, CloudFront talks to uvicorn directly. 025 decides between trusting
  `X-Forwarded-For` (spoofable leftmost entry) and the `CloudFront-Viewer-Address` header through an
  origin request policy.
- **One instance:** by construction, with no instance count to set. The runbook already says scaling out
  needs a shared rate-limit store. **Never sleeps:** 025 AC 14 and 026 AC 12 are dropped.
- **Deploys:** the role `cragmatch-github-deploy` (trust: `main`) and the repository variables
  `AWS_DEPLOY_ROLE_ARN` and `AWS_REGION`. 025 attaches ECR push plus `ssm:SendCommand` on the host's ARN
  and `AWS-RunShellScript`; 026 attaches S3 `PutObject`/`DeleteObject`/`ListBucket` on the site bucket
  and `cloudfront:CreateInvalidation`. Gate on `CI` with `workflow_run` or `needs:` (018's names). The
  arm64 image is built on an `ubuntu-24.04-arm` runner, or with buildx and QEMU, or on the host itself.
- **026 hosting:** a private S3 bucket with CloudFront OAC and the default certificate, an SPA fallback
  (custom error response or CloudFront Function), within the free allowances. Create the hosting first
  and read its domain for `CRAGMATCH_CORS_ORIGINS`.
- **Costs:** 025 and 026 add rows to the runbook table (about +0.2 USD in total) and keep the budget.
