# CragMatch on AWS: runbook

Ticket 024 builds the foundation. Tickets 025 (backend) and 026 (frontend) add sections here.
All commands are PowerShell, run by you. Nobody else runs `plan` or `apply` against your account.
No real account id, email or key is ever committed: they live in `terraform.tfvars` and
`backend.hcl`, both gitignored.

## 1. What this builds and why

- One small Graviton EC2 host (`t4g.small`, Amazon Linux 2023) in one public subnet of one VPC, whose
  **only inbound rule is TCP 80 from CloudFront's prefix list** (section 14; 5432 stays closed), and outbound TCP 443 and 80 only (80 is for the signed apt repositories). Admin access is SSM Session Manager (no SSH, no key pair).
- Postgres 17 with PostGIS and pgvector runs on it in a container (`infra/main/host/db/Dockerfile`),
  published only on the host's `127.0.0.1:5432` and on the Docker network `cragmatch` as `db:5432`.
  TCP connections need TLS and a password.
- The data is on its own encrypted EBS volume that survives host replacement, with a daily snapshot
  kept 7 days (AWS Data Lifecycle Manager).
- The database password is generated by Terraform as an ephemeral value and written as a write-only
  SSM SecureString: it is in neither the plan nor the state.
- Terraform state is in a versioned, encrypted S3 bucket with an S3 lockfile (no DynamoDB). A small
  `bootstrap` stack creates that bucket.
- A monthly budget emails you at 50 % and 100 % of 11.20 USD (about 10 EUR) and on the forecast.
- Every resource carries the tag `Project = cragmatch` (provider `default_tags`).
- A GitHub OIDC role `cragmatch-github-deploy`, trusted only for this repository's `main` branch. It
  has no permissions yet; 025 and 026 add them.

**Region `eu-west-1` (Ireland).** Same `t4g` price as Spain, cheaper RDS, every service on by default.
`eu-south-2` needs an opt-in step. The region is a variable.

**Why a public subnet and no database "in a private subnet".** A private subnet would need a NAT
gateway (about 35 USD a month) to reach Claude, Voyage and huggingface.co, because they have no IPv6.
The protection is the single CloudFront-only inbound rule, loopback binding, and TLS plus a password.

**One host means one backend instance.** The rate limits live in memory. Scaling out needs a shared
rate-limit store (a new ticket).

Options compared (USD a month, 730 hours, eu-west-1, after any trial):

| Option | Cost | Verdict |
|---|---|---|
| A. One `t4g.small`, backend and Postgres containers | about 18.6 for 024 | Chosen. You own upgrades and backups. |
| A'. Same on `t4g.micro` | about 11.9 | Cut 1, only if memory fits. |
| B. RDS `db.t4g.micro` plus a host | about 32.7 | Over budget. RDS 17 does offer PostGIS and pgvector. |
| C. Aurora Serverless v2 | about 51 | The app holds connections open, so it never pauses. |
| D. ECS Fargate plus ALB | 27 or more | Out. |
| E. Lambda | NAT gateway 35 | Out. |
| F. App Runner | n/a | Closed to new customers. |

## 2. Account set-up (manual)

1. Create the AWS account. The **Free plan** closes the account after 6 months unless you upgrade, and
   the data is deleted 90 days later. The **Paid plan** applies the credits first and then bills.
   Read the credit expiry date on your own Credits page (the FAQ says 6 or 12 months). If the new
   sign-up asks you to activate advanced features for IAM roles or regions, do it.
2. Turn on MFA for the root user.
3. Create an admin IAM user with console access and MFA.
4. Log in from the CLI, with no access keys anywhere:
   ```powershell
   aws login --profile cragmatch
   aws configure export-credentials --profile cragmatch --format powershell | Invoke-Expression
   ```
5. Before every apply, check the account:
   ```powershell
   aws sts get-caller-identity
   ```
   It must show the CragMatch account. This machine may hold credentials for others;
   `allowed_account_ids` also refuses a wrong account.
6. Install Terraform >= 1.11 (1.16.6 recommended) and the Session Manager plugin for the AWS CLI.

## 3. Bootstrap (once)

```powershell
cd infra\bootstrap
Copy-Item terraform.tfvars.example terraform.tfvars   # then set aws_account_id
Set-Content backend_override.tf 'terraform { backend "local" {} }'
terraform init
terraform apply
terraform output -raw backend_config | Set-Content ..\backend.hcl
Remove-Item backend_override.tf
terraform init -migrate-state -backend-config=..\backend.hcl   # answer yes
Remove-Item terraform.tfstate*
```

The bucket `cragmatch-tfstate-<account>-<region>` holds the state of both stacks. It is versioned
(old versions expire after 90 days), encrypted, private and TLS-only. Locking is a `.tflock` object
next to the state file while a run is active.

## 4. Apply the foundation

```powershell
cd infra\main
Copy-Item terraform.tfvars.example terraform.tfvars   # then fill in the three placeholders

terraform plan -detailed-exitcode   # must exit 0
```

AWS sends a confirmation email for the budget subscription only if the address is new to Budgets;
check the inbox. The host builds the database image at first boot, which takes several minutes.

## 6. Where secrets live and what the state contains

- The database password: made by Terraform, stored at `/cragmatch/db/password` (SecureString), never
  in the state or the plan. The host reads it at boot.
- The Anthropic and Voyage keys: ticket 025 creates `/cragmatch/api/anthropic_api_key` and
  `/cragmatch/api/voyage_api_key`; you type the values in by hand, never on a command line that
  history keeps.
- The state holds ids, ARNs (which contain the account id), the public IP and your email, in a
  private encrypted bucket.
- `backend/.env` is never used in the cloud.

## 10. Backups and restore

Daily snapshots at 03:00 UTC, kept 7 days, crash-consistent (Postgres recovers like after a power
cut). The data CragMatch cannot reload with ticket 023 is groups, members and planner runs.
```powershell
aws ec2 describe-snapshots --owner-ids self --filters Name=tag:Backup,Values=cragmatch-daily
```
Restore either by creating a volume from a snapshot, running `terraform state rm aws_ebs_volume.data`
and `terraform import aws_ebs_volume.data <new volume id>`, or by moving the data with `pg_dump`
through SSM port forwarding.

## 11. Host operations

- Shell: `aws ssm start-session --target <host_instance_id>`.
- Boot log: `/var/log/cloud-init-output.log`. Database log: `sudo journalctl -u cragmatch-db`.
- Re-run the setup (safe): `sudo bash /opt/cragmatch/host-setup.sh`.
- OS update or replacement (data kept, a few minutes down; the AMI is pinned on purpose, so replace
  monthly or run `sudo dnf upgrade` through SSM): `terraform apply -replace=aws_instance.host`.
- Password rotation (the new value only exists after the apply, and a typed password lands in
  psql history, so the order matters):
  1. Bump `db_password_version` in `terraform.tfvars` and `terraform apply`.
  2. On the host: `sudo bash /opt/cragmatch/host-setup.sh` (rewrites `/etc/cragmatch/db-environment`).
  3. Still on the host, read the new value into a variable without echoing it
     (`P=$(aws ssm get-parameter --region eu-west-1 --with-decryption --name /cragmatch/db/password --query Parameter.Value --output text)`),
     then run `sudo docker exec -it db psql -U cragmatch` and use `\password cragmatch`, pasting the
     value. Clear it afterwards with `unset P`.
  4. Restart the units that read the password (`sudo systemctl restart cragmatch-db`, then
     `sudo systemctl restart cragmatch-api`).
- Postgres major upgrade (17 to 18) is a manual dump and restore.
- The app user is the database superuser (as locally), so the planner's `setup()` and
  `CREATE EXTENSION` work. The certificate is self-signed and lives on the data volume.

## 12. Destroy

1. Optional final dump through SSM port forwarding.
2. In `infra/main`: `terraform destroy`. **The data volume and the database are lost.**
3. What stays and still bills: the DLM snapshots (about 0.05 per GiB-month; list them by tag and
   delete them) and the state bucket.
4. To remove the bootstrap too: set `allow_destroy = true` and apply; move its state back to local
   (create `backend_override.tf` again and run `terraform init -migrate-state`); then
   `terraform destroy`, which empties and deletes the bucket with all its versions.
5. Closing the account stops everything else.

## 14. Backend: what it adds

Ticket 025. The request path: phone, CloudFront (HTTPS), host port 80 (open to CloudFront only), the
`api` container, `db` over verified TLS.

- **ECR** repository `cragmatch-api` (immutable commit-SHA tags, the newest 5 kept).
- **The API unit** `cragmatch-api.service` runs one container named `api` next to Postgres. The image
  is the one from ticket 021 (one worker).
- **An API CloudFront distribution** with caching off and the default `*.cloudfront.net` certificate.
  It is separate from the site's (ticket 026).
- **Parameter Store** holds the settings and the two key slots under `/cragmatch/api/`, and the host id and
  API address under `/cragmatch/deploy/`.
- **Logs** go to the CloudWatch group `/cragmatch/api` (14 days).
- **The `Deploy` workflow** builds the image after `CI` passes on `main` and deploys it through the SSM
  document `cragmatch-deploy-api`.

Things to know:
- **TLS trade-off.** CloudFront to the host is plain HTTP: CloudFront refuses self-signed origin
  certificates and we have no domain for a public one. Search text, group names, member names and grades
  cross that hop unencrypted; there are no passwords or logins. The upgrade path is a custom domain.
- **Exactly one instance.** One host, one unit, one container name. Scaling out needs a shared
  rate-limit store (a new ticket), because the limits live in memory.
- **Never sleeps.** There is no wake-up delay. Cut 2 (section 8) is planned downtime: CloudFront
  answers 502 or 504 and the web app shows its offline state.
- **Client address.** uvicorn trusts `X-Forwarded-For` only from CloudFront's ranges
  (`FORWARDED_ALLOW_IPS`, rendered from AWS's managed prefix list). It must never be `*`, which would take
  the leftmost entry that a viewer controls. If AWS adds a range before your next `apply`, viewers from it
  share one limit (stricter, never spoofable).
- **Changing any file under `infra/main/host/` replaces the host** on apply: a few minutes down, data kept.
- **A deploy restarts the API:** about 10 to 30 seconds of 502 or 504.

## 16. Backend: load the data (once, safe to repeat)

The database is on the host, with no inbound rule, so the laptop reaches it through SSM port forwarding.
`import_stays` runs on the laptop, because Overpass and its cache are there.

Window 1:
```powershell
aws ssm start-session --target (terraform output -raw host_instance_id) --document-name AWS-StartPortForwardingSession --parameters portNumber=5432,localPortNumber=15432
```
Window 2, in `backend/`:
```powershell
$p = aws ssm get-parameter --name /cragmatch/db/password --with-decryption --query Parameter.Value --output text
$env:CRAGMATCH_POSTGRES_URL = "postgresql://cragmatch:$p@127.0.0.1:15432/cragmatch?sslmode=require"
Remove-Variable p
uv run python -m app.scripts.load_data
```
Check that the first line shows `127.0.0.1:15432/cragmatch`, then answer `y`. It makes 1 Voyage request
with the laptop's key. Then:
```powershell
Remove-Item Env:CRAGMATCH_POSTGRES_URL
```
and close both windows.

**Never run pytest in that window.** Wait a minute before a vibe search (Voyage allows 3 a minute). A
second run prints "0 added".

## 19. Backend: roll back

- Actions, `Deploy`, "Run workflow" from `main` with `image_tag` = the previous SHA and `skip_migrations`
  ticked.
- Or from the laptop:
  ```powershell
  aws ssm send-command --document-name cragmatch-deploy-api --instance-ids <id> --parameters imageTag=<sha>,runMigrations=no
  ```
- **A rollback never undoes a migration.** An older image does not know a newer revision, so a rollback skips
  migrations. Rule: migrations only add (columns nullable or with defaults, no renames or drops in the
  same release), so the previous image still works.
- An unhealthy deploy returns to the previous image by itself and the run goes red.

## 20. Backend: change keys, caps and CORS

- Keys: overwrite them in Parameter Store, then `sudo systemctl restart cragmatch-api` in a session (or run
  `Deploy` by hand with the live SHA).
- Caps: edit `terraform.tfvars` (`claude_daily_cap_usd`, `voyage_daily_cap_usd`), `terraform apply`, then
  restart the same way. The CORS origin is not a setting any more: it is the site's address (section 24).
- The CloudFront ranges: `terraform apply` refreshes `FORWARDED_ALLOW_IPS`, then restart.

## 24. Web: what it adds

Ticket 026. The request path: phone, CloudFront (HTTPS), a private S3 bucket read through origin access
control. The site has its own distribution, separate from the API's.

- **Cache rules.** Hashed files under `assets/` are cached for a year and marked `immutable` (the name changes
  whenever the content does). `index.html` is `no-cache`, so browsers revalidate it on every load. Each deploy
  invalidates `/*` once and waits for it, so a green `Deploy` means everyone sees the new version.
- **Two releases are kept.** A deploy keeps the assets of the new and the previous release and prunes older
  ones only after the invalidation. A visitor with the previous version open can still load its lazily
  fetched files (a font subset, for example). Never run `aws s3 sync --delete` on the bucket.
- **Unknown paths open the app.** S3 answers 403 for a missing key, and the distribution turns 403 and 404
  into `index.html` with status 200.
- **Security headers** (our own policy `cragmatch-web-security`): HSTS for a year, `nosniff`, `X-Frame-Options:
  DENY`, `Referrer-Policy: no-referrer` (the share link's `?group=CODE` never leaves in a Referer) and a CSP
  that allows scripts, styles, fonts and images from the site itself and connections to the site and the API's
  address only. A future external call (maps, analytics) must add itself to `local.web_csp` in `web.tf`.
- **The API allows only the site's origin** (`CRAGMATCH_CORS_ORIGINS` is the web distribution's address,
  written by Terraform). So `npm run dev` against the cloud API is refused; use the local backend.

## 25. Web: first deploy

Order matters only for the running API, which picks up the new origin at its next start.
1. Apply from the working copy **before pushing**. If `terraform.tfvars` still has a `cors_origins` line,
   delete it first. The apply creates the bucket, the distribution (5 to 15 minutes), the deploy policy and
   three `/cragmatch/deploy/web_*` parameters, and rewrites `/cragmatch/api/settings`. The host is not
   replaced:
   ```powershell
   cd infra\main
   terraform plan
   terraform apply
   ```
2. Push. `CI` goes green, then `Deploy backend` re-renders the API environment and restarts the container (the
   API now allows the site), then `Deploy web` builds and publishes. If you applied without pushing, run
   `Deploy` by hand with the live SHA.
3. Open the site:
   ```powershell
   terraform output -raw web_url
   ```

## 26. Web: redeploy and what is live

- Every green `CI` on `main` deploys the backend, then the web app: both, always.
- The `Deploy` run ends with `Live web: <sha>`.
- The live commit and its files:
  ```powershell
  aws s3 cp ("s3://" + (terraform output -raw web_bucket) + "/release/current.txt") -
  ```
  `previous.txt` in the same folder is the release before.

## 27. Web: roll back

- Actions, `Deploy`, "Run workflow" from `main` with `image_tag` = the previous SHA and `skip_migrations`
  ticked. Both parts return to that commit: `Deploy web` rebuilds it with today's API address. The
  publish script always comes from the commit the workflow runs on, so the target may be older than 026.
  A target from before ticket 021 does not read the API address at build time, so its site would call the
  wrong API: roll back to 021 or later.
- The previous release's assets are still in the bucket, so pages that are open keep working.
- A web-only rollback is not offered (simple and predictable).

## 28. Web: destroy

- `terraform destroy` (section 22) also removes the bucket with its files (`force_destroy`), the web
  distribution (disabling takes minutes), its policies and the three parameters.
- Removing only the web hosting is a code change (delete `web.tf`, point CORS elsewhere) followed by an apply.
  Never use `-target`: it would also destroy `/cragmatch/api/settings`, which depends on the site.
